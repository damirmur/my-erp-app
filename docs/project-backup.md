# Выгрузка и загрузка проекта через JSON-файл

Перенос структуры таблиц и данных между проектами my-erp-app через кнопку **«💾 Резервная копия»** в Конструкторе.

## Что переносится

Один JSON-файл содержит срезы всех 6 таблиц Supabase (uuid сохраняются — на них держатся все ссылки):

| Секция | Что это |
|---|---|
| `metaTableTypes` | Кастомные типы таблиц |
| `metaTables` | Структура: таблицы + `config` (в т.ч. `runCode` действий) |
| `metaColumns` | Реквизиты: колонки, типы, ссылки `related_table_id` |
| `dataRecords` | Все записи: документы, справочники, сценарии, печатные формы, сервисы, настройки |
| `dataLines` | Строки табличных частей |
| `dataFiles` | Вложения (base64) |

## Необходимые требования

1. **Тот же код приложения** на обоих проектах (или новее — совместимый).
2. **Свой Supabase у нового проекта**: `PUBLIC_SUPABASE_URL` и `PUBLIC_SUPABASE_ANON_KEY` из `.env` должны указывать на него (см. `.env.example`).
3. **Схема БД в новом проекте** — таблицы и ENUM-типы должны существовать до импорта. Иначе вставка упадёт: enum `column_type` не содержит `file/zip/datetime/universal/linelink/select/paramslist`, а таблиц `meta_tables` и т.д. нет вообще.
4. **Интернет** на время выгрузки и загрузки (импорт пишет напрямую в Supabase).
5. **Свободный новый проект**: импорт работает в режиме «замена» — все данные текущего проекта будут удалены. Переносить в непустой проект нельзя (мерджа нет).

### Схема БД: два способа подготовить новый проект

**Вариант A (рекомендуется) — `supabase db push`:**

Для облачного Supabase команда выполняется **на вашей локальной машине** (или в CI), а не «в облаке»: CLI из терминала применяет файлы репозитория к удалённой базе.

```bash
# 1. Установить Supabase CLI (если ещё нет)
npm install supabase --save-dev          # или глобально: npm i -g supabase

# 2. Войти (откроет браузер с авторизацией)
supabase login

# 3. Привязать локальную папку к облачному проекту
#    (ref — из Dashboard → Project Settings → Reference ID)
supabase link --project-ref <project-ref>

# 4. Применить миграции из supabase/migrations/ к облачной БД
supabase db push
```

Нюансы `db push` для облачного проекта:
- Применяет к **удалённой** базе только файлы из `supabase/migrations/`, которых ещё нет в `schema_migrations` облачного проекта. Всё остальное локальное (`.env`, `config.toml`) на базу не влияет.
- `supabase link` выполняется один раз; `project_ref` и `--password` можно прописать в `supabase/config.toml`, чтобы не вводить их каждый раз.
- Применит все миграции 0001–0010 одной командой (трекнинг `supabase_migrations.schema_migrations` останется полным).

**Вариант B — `supabase/init_full.sql` (одним файлом):**
```bash
psql "$DATABASE_URL" -f supabase/init_full.sql
```
или: Supabase Dashboard → **SQL Editor** → вставить содержимое `supabase/init_full.sql` → **Run**.

Для разовой настройки нового проекта SQL Editor — самый простой вариант: ничего устанавливать и линковать не надо.

`init_full.sql` — самодостаточный идемпотентный эквивалент миграций 0001–0010 (все `IF NOT EXISTS`/`OR REPLACE`/DO-блоки). Создаёт только схему — данные сидов системных таблиц приложение создаст само при первом запуске. Его можно применять повторно без ошибок. Для существующих инсталляций его применять не нужно (и не вредно) — история миграций не затрагивается.

## Последовательность действий

### Подготовка нового проекта

1. Задеплойте код приложения (тот же `my-erp-app`).
2. Создайте проект Supabase и получите его `URL` + `anon key`.
3. В `.env` нового проекта пропишите:
   ```
   PUBLIC_SUPABASE_URL=<URL нового проекта>
   PUBLIC_SUPABASE_ANON_KEY=<anon key нового проекта>
   ```
4. Примените схему БД (**Вариант A** или **B** выше).
5. Соберите и запустите: `npm run build` / `npm run dev`.

### Выгрузка (на исходном проекте)

1. Откройте приложение → **Конструктор**.
2. В секции **«💾 Резервная копия»** отметьте при необходимости **«Включить системные таблицы»** (по умолчанию включено — переносит сценарии, печатные формы, сервисы API, настройки меню; отключите, если нужны только пользовательские таблицы).
3. Нажмите **«📤 Выгрузить проект»** — скачается файл `my-erp-backup-ГГГГ-ММ-ДД.json`.
4. Проверьте сводку в сообщении (количество таблиц/реквизитов/записей/строк/вложений).

### Загрузка (в новый проект)

1. Откройте **новый** проект → **Конструктор** → **«💾 Резервная копия»**.
2. Нажмите **«📥 Загрузить проект…»** и выберите JSON-файл.
3. Подтвердите замену данных.
4. Дождитесь сообщения об импорте — приложение автоматически:
   - очистит локальный кэш (IndexedDB);
   - сбросит локальные настройки (`clearAppStorage`);
   - перезапустится (жёсткий reload).
5. После перезапуска `pullMetadata`/`pullDataChanges` скачают всё из импортированных данных.

## Ограничения

- **Размер**: файлы хранятся как base64 (до 20 МБ каждый). Для очень больших проектов выгрузка может быть тяжёлой — предупреждение о лимите объёма запланировано как улучшение.
- **Офлайн**: экспорт пагинирован по 1000 строк на запрос и требует сервер; импорт — только онлайн.
- **Системные таблицы**: при импорте с включёнными системными таблицами сиды нового проекта найдут таблицы по имени и не перезапишут импортированные данные.
- **Версия выгрузки**: файл содержит `format`/`version`; при несовпадении импорт отклонит файл с понятной ошибкой.
