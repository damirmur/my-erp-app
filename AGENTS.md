# my-erp-app

Low-code ERP system built with Svelte 5 + SvelteKit 2. Offline-first via Dexie/IndexedDB, Supabase for cloud sync.

## Commands

| Command           | Purpose                                |
| ----------------- | -------------------------------------- |
| `npm run dev`     | Dev server at `http://10.66.66.9:5173` |
| `npm run build`   | Production build                       |
| `npm run check`   | Type-check only (`svelte-check`)       |
| `npm run lint`    | Prettier format check                  |
| `npm run format`  | Prettier auto-format                   |
| `npm run prepare` | Run `svelte-kit sync` after install    |

Run `npm run check` before committing. No test suite exists.

## Architecture

- **Metadata-driven**: No hardcoded forms. Components (`DynamicForm`, `DynamicList`, `TabularSection`) render from table/column definitions fetched from IndexedDB.
- **Single route** (`/`): Entire app is an SPA with tabbed workspace managed via `src/lib/state/workspace.svelte.ts` (Svelte 5 runes).
- **Deep links (hash)**: every table/record/ТЧ row has a unique link `#/t/{id|name}`, `#/r/{recordId}`, `#/l/{lineId}`. Parsing/building/resolution in `src/lib/services/deeplink.ts` (`parseHash`, `buildUrl`, `resolveUrl`); `resolveUrl(href)` returns `{ table, columns, record?, lines? }` — record field values live in `record.data[columnName]`. Available to `runCode` as the `link` helper. Active tab is mirrored to the hash via `replaceState` from `$app/navigation`; `hashchange` in `+page.svelte` reopens objects. **API-режим (JSON по ссылке, без открытия формы)**: `#/t/{id}.json` (список), `#/r/{id}.json` (запись+ТЧ), `#/r/{id}.execute({...}).json` (выполнить код действия таблицы по записи с параметрами) — новые kinds `listJson`/`recordJson`/`execute`, параметры разбираются `parseParamsLiteral` (JS-литерал без кавычек или JSON, безопасно, без eval); исполнение в `src/lib/services/apiCommand.ts` (`runApiCommand`) → результат в `workspace.apiResult` → панель «API» (`ApiResultModal.svelte`, рендерится в `+page.svelte`); для сценариев панель показывает пошаговые статусы узлов (`steps`: ok/error/pending, текст ошибки, время), причём панель открывается **только при ошибке** (успешный прогон не перекрывает экран), а сам прогон всегда пишется в «Историю». В `runCode` доступна переменная `params` (параметры из ссылки); `return` кодa действия показывается в панели «API» (form/list `handleRun` → `workspace.showRunResult`/`workspace.showApiResult`; `showRunResult` помечает результат сценария полем `flow` и передаёт в `showApiResult`, который для `result.flow` вызывает `recordFlowRun` — запись в историю — и открывает панель только при ошибке). Из `runCode` ссылки генерируются через `link.execute(id, params?)`/`link.recordJson(id)`/`link.listJson(id)`. Changes (saves, deletes and flow runs only — **opens are not logged**) are recorded in a real system table «История» (`meta_tables.name='history'`, `type='system'`): each operation is a separate `data_records` row via `workspace.recordHistory(tableId, title, link, 'save'|'delete'|'run', status?, extra?)` with `data = { object_title, link, opened_at, event, event_type, ...extra }`. Save events fire from `DynamicForm.saveToDb` and `saveRecordWithLines` (runCode `save()`), delete events from `physicalDeleteRecords` (titles captured from the cache before deletion), flow runs from `recordFlowRun` (extra = `{ failed, description, steps, error, result }`, event = «выполнение сценария (ошибка)»/«выполнение сценария», link ведёт на сценарий). «Событие» column shows the label; «Описание» (`description` column, ensured by `ensureHistoryColumns`) — читаемое резюме прогона (статусы шагов, ошибки, результат); rows sync like any data, capped at 50. Sidebar «🕘 История» opens it as a `DynamicList`; a row click opens the history record itself as a read-only form (`DynamicList.openRecord`, system tables open as a normal form, `DynamicForm` forces `readOnly` for `type==='system'`). Seeded idempotently by `metadata.ensureSystemTables()` (startup + start of each sync, before `pullMetadata`); `ensureHistoryColumns` adds missing columns to existing installs. See `architecture.md` → Deep Links.
- **Sidebar (main mode)** (`src/lib/components/layout/Sidebar.svelte`, liveQuery-driven): tables grouped by type, «🔗 Открыть ссылку» (paste `#/t/...`/`#/r/...`/`#/l/...` or a bare id → `workspace.openFromLink()`), «🕘 История». Group/table order is editable in Конструктор («🔀 Порядок меню») and persisted in the system table `app_settings` (`src/lib/state/settings.ts`, key `main_nav_order`, synced like data); «Сброс» restores defaults, unset → `preferredTypeOrder` + `sort_order`/`number`.
- **Notifications module** (`src/lib/state/notifications.ts`): seeded idempotently by `ensureNotificationTables()` (called from `metadata.ensureSystemTables()`). Catalog «Сервисы API» (`api_services`) with a `proxy` self-link (via proxy gateway when filled, direct fetch when empty); `notify_channels` (with `service` link → api_services); document «Сообщение» (`notify_messages`); tabular part «Контакты» of counterparties (`contragent_contacts`, parent → `counterparties`, rows: `channel` + `value`); message ТЧ «Получатели» (`notify_message_channels`, rows: `kontragent` → counterparties + optional `channel`). Legacy `notify_recipients` catalog was removed (seed no longer creates it). Seed also adds the «OpenStreetMap — геокодинг (Nominatim)» service (number '8', `base_url` with `${query}`) and reconciles missing default services by `name` via `serviceExists()` (idempotent re-seed for existing installs). Action code `NOTIFY_RUN_CODE` (matches server-side, updated via `RUN_CODE_LEGACY` markers) resolves recipient ids from counterparty contacts, groups by service and sends via `apiCall`. `apiCall(service, params?, body?)` (`src/lib/services/actionRunner.ts`) substitutes `${param}` (URL-encoded) in `base_url`, applies auth (`auth_type` query/header), routes through proxy (`d.proxy` link → proxy service's `base_url` + its `api_key`) with backwards compat `use_proxy === true` → `https://astro3d.ru/api/proxy`. Returns `{ ok, status, data, raw }`.
- **API-queries catalog** (`src/lib/state/apiQueries.ts`): system document «API-запросы» (`api_queries`) — each record is one external call: `service` link → api_services + `params` (jsonb defaults) + optional runCode. Seeded idempotently by `ensureApiQueryTables()` (from `metadata.ensureSystemTables()` after notifications) + `seedApiQueryDefaults()` in `sync.runFullSync` (after `seedNotificationDefaults()`); seed example «Погода (wttr.in)» finds the wttr service by name. Executed declaratively when runCode is empty: `runRecordAction` (`src/lib/services/actionRunner.ts`) merges defaults with call params via `mergeParams(record, linkParams)` = `{ ...record.data.params, ...linkParams }` (link wins by key) and calls `apiCall(service, params)`; falls back to `apiCall(record, params)` for records with own `base_url`. Form/list `handleRun` now delegate to `runRecordAction` (result → «API» panel), so ▶️ works for both coded and declarative records.
- **Bank statements module** (`src/lib/state/bankStatements.ts` + `src/lib/services/bankParser.ts` + `src/lib/services/pdfText.ts`): import of bank statement PDFs (СберБанк Онлайн, Альфа-Банк и др.), seeded idempotently by `ensureBankStatementTables()` (from `metadata.ensureSystemTables()` after flows) + `seedBankStatementDefaults()` in `sync.runFullSync`. Tables: «Банки» (`banks`, catalog — each record = `bank_hints` маркеры распознавания + `parser_code` код-парсер формата в песочнице, редактируется в UI; новый банк/вид выписки = новая запись без пересборки; заводской парсер обновляется автоматически только если запись не редактировалась — legacy-сверка по `SBER_PARSER_CODE_LEGACY`), «Банковские счета» (`bank_accounts`, catalog: `bank` → banks, `account_number`), «Выписки» (`bank_statements`, document: `account` → bank_accounts, `bank` → banks (опц., автоопределение по hints), `file` PDF, `period_start/end`, `opening/closing_balance`, `currency`, `statement_type` — заполняется парсером: «Счёт»/«Дебетовая карта»/«Кредитная карта», `operations_count`, `last_result`) + ТЧ «Операции» (`bank_statement_operations`: `op_date`, `op_time`, `auth_code`, `category`, `description`, `amount` со знаком «+»=приход/без знака=расход, `balance`, `extra` jsonb). Текст PDF извлекается на клиенте через `pdfjs-dist` (`extractPdfText`, координатная экстракция `rows` по y + ячейки по x — для многостолбцовых таблиц; pdf.js грузится лениво `import('pdfjs-dist')`, чтобы не падать в SSR/Node). Импорт запускается «▶️ Выполнить» (`config.runCode = BANK_STATEMENT_RUN_CODE` → `importStatement(record.id, params)` из `runCode`-контекста, работает и по `#/r/{id}.execute().json`): определяет банк (поле → банк счёта → автораспознавание по `bank_hints`), выполняет `parser_code` банка (контекст парсера: `text`, `rows`, `helpers` — `num`/`amount`/`date`/`hint`; возвращает `{ header, operations }`), заполняет шапку, автосоздаёт/привязывает запись «Банковского счёта» (по банку+номеру счёта), заполняет ТЧ с дедупликацией по ключу `дата|время|код|сумма`, возвращает сводку (counters) в «API»-панель. Парсер Сбера (`SBER_PARSER_CODE`) распознаёт вид выписки по заголовку («Выписка по платёжному счёту» / «кредитной карты» / «дебетовой карты») и разбирает блоки «дата время категория сумма остаток» + строки описания «дата код …», отбрасывая колонтитулы страниц и финальный блок «Дата формирования документа». Парсер Альфы (`ALFA_PARSER_CODE`) разбирает строки «дата код описание … сумма RUR» (продолжения описания до следующей даты+кода), пропускает секцию неподтверждённых операций (`HOLD`). Зависимость: `pdfjs-dist` (`pdf.worker.min.mjs` через `?url`, декларация `*?url` в `src/app.d.ts`).
- **Print forms module** (`src/lib/state/printForms.ts` + `src/lib/services/printer.ts`): registry «Печатные формы» (`print_forms`, type `template` «Шаблон», `config.hiddenInMain: true` — hidden from main mode, edited in constructor) seeded idempotently by `ensurePrintFormsTable()` (from `metadata.ensureSystemTables()` after bank statements; reconciles type to `template` if an earlier version created the table as `document`) + legacy migration `seedPrintFormDefaults()` in `sync.runFullSync` (copies rows from the old raw Supabase `print_forms` table — `template_html` — into `data_records`, then deletes them). Columns: `number`, `name`, `target_table` (select «Таблица» — options = all top-level tables via `flowElements.loadSelectOptions`, title shown in `DynamicList` via `tableTitleMap`), `template_html` (textarea «Шаблон HTML»), `code` (textarea «Код заполнения»), `is_default` (boolean «По умолчанию»), `sort_order`. Button «🖨️ Печать» (`Toolbar.svelte`, liveQuery-driven): **0 форм → кнопка скрыта**, 1 форма → прямая печать, несколько → выпадающий список (дефолт ✓), в списке печать выделенных записей с выбором формы. Renderer `printerService.printRecords(tableId, recordIds, formId?)` reads `template_html` (not `template`) and uses a universal mustache-like engine (`renderTemplate` in `printer.ts`): `{{field}}`/`{{doc.field}}` — any record column (formatted by type via `formatFieldValue`, link columns resolved to names), `{{doc.title}}`, `{{doc.total_amount}}` (sum of `amount` over all lines), `{{#each <ТЧ>}}…{{this.field}}…{{@index + 1}}{{/each}}` (any tabular part by name; legacy `{{#each lines}}` = first ТЧ, innermost blocks first), `{{sum:<ТЧ>:<field>}}`, `{{count:<ТЧ>}}`. **Поле `code`**: JS в песочнице `runActionCode` (контекст `record`, `records`, `lines`, `subLines` = имя ТЧ → строки, `params`, `db`, `supabase`, `save`, `log`, `link`, `apiCall`, `run`, `flowLayout`); возвращает строку HTML (используется как есть) или объект данных, который рендерится макетом через `{{form.<key>}}` / `{{#each form.<name>}}…{{this.<key>}}…{{/each}}`; ошибки кода выводятся в окне печати красным. Нет `code` → рендер макета по-старому. Банковская специфика (месячная группировка) живёт только в записи печатной формы (данные), движок её не знает. Values HTML-escaped; output opened in a print window. The old raw `print_forms` Dexie table is removed (`indexeddb.ts`, `sync.ts`, `Workspace.svelte`). Печатная форма **«Сценарий»** (для `flow_scenarios`): `code` строит SVG-схему графа через `flowLayout(subLines['flow_nodes'], subLines['flow_links'])` — волны-колонки «Шаг N», стрелки с ролями и подписями, карточки узлов с бейджами типов (📌/🪝/🌐/🖼/🔍/➕/🏃/🧩), красная рамка для узлов вне порядка + предупреждение о цикле — и возвращает `{ cards, edges, waves, cycleWarn, width, height, markerId }`, который макет рендерит в SVG через `{{#each form.cards}}`/`{{#each form.edges}}`/`{{#each form.waves}}`. Раньше схема жила в форме сценария (компоненты `FlowDiagram.svelte`/`FlowRefsPanel.svelte`) — удалены из `DynamicForm`.
- **Flow/scenario type** (`flow`, `src/lib/table-types/flow.ts` + `src/lib/state/flows.ts`): a table type «Сценарий» whose record is an n8n-like graph. Nodes and edges live in ТЧ (seed `ensureFlowTables` from `metadata.ensureSystemTables()`): «Узлы» (`flow_nodes`, rows: `name`, `element` — link → каталог `flow_elements`, `node_type` — `select` fed by `flowElements.selectOptionsFor`, `service` link → api_services, `params` jsonb — переопределения поверх элемента, `code`) and «Связи» (`flow_links`, rows: `from_node`/`to_node` — `linelink` fields, `role` flow|parallel|input, `label`). Catalog **«Элементы сценария»** (`flow_elements`, type `directory`, seeded idempotently by `seedFlowElements`): reusable node configs (`element_type` select, `service`, `params`, `code`, `icon` — значок типа, заполняется автоматически по `element_type`); a node references an element and may override params/service/code — the engine merges defaults with overrides (priority: inputs > node overrides > element defaults), legacy factory configs reconciled via order-insensitive `deepEqual`. Execution engine `src/lib/services/flowRunner.ts` (`flowExecute(recordId, params)`): wave-based topological run — a node fires when all incoming edges are satisfied, ready nodes run in parallel (`Promise.all`), each node's result is added to an accumulated `context` (by node title + merged keys) so later nodes reference earlier results via `${имя_узла}`/`${input}`/`${key}` substitution; returns `{ results, last, steps }` — `steps` carries per-node status (`ok`/`error`/`pending`, error text, durationMs) shown in the «API» panel. Node types in `src/lib/services/flowElements.ts` (`runFlowElement`): `constant` (read constant by name), `get` (JSON path extract, passthrough for scalars), `api` (apiCall with `${...}` substitution), `template` (text with `${path}`), `find` (record/ТЧ-line lookup by `where`; `all: true` returns ALL matches as an array, array `where` values mean «in», `map` reshapes rows for `lines`; local IndexedDB first, then Supabase fallback — always attempted (no `navigator.onLine` gate) querying both local and server table ids, found lines cached), `create` (record + ТЧ lines via `saveRecordWithLines`; `lines` accepts an array from context), `run` (runAnotherTable). `substitute` preserves the type of an exact `${path}` value (arrays/objects), so a whole `lines` spec or a `where` list can come from context. Dispatch in `flowRunner.executeNode`: element types → `runFlowElement`, else service → apiCall, else `code` → runActionCode (context gains `flow`, `input`, `inputs` in `actionRunner.ts`). Triggered by ▶️ (runRecordAction dispatches flow type when no runCode) or default `config.runCode = return await flow(record.id, params)`. Scenario «Параметры» (jsonb) is an editable column of `flow_scenarios`; `mergeParams` merges them with link params (and parses `data.params` stored as JSON string). Field types added for this: `linelink` («Ссылка на строку ТЧ», `LineLinkField.svelte` — dropdown of a sub-table's rows for the current record, candidates passed from form memory before save) and `select` («Выбор из списка», `SelectField.svelte` — options passed per column via `selectOptionsFor`). Postgres enum values added by migrations `0006_add_linelink_column_type.sql` and `0007_add_select_column_type.sql`. Idempotent seed example «Погода → сообщение (пример)» (`seedFlowExample` in `sync.runFullSync`) builds a working graph (constant city → get → wttr API → template → `find.all` contacts for the `kontragents` array → create notify_messages with recipient lines from context → run send); a legacy inline example is auto-deleted and recreated in the new format.
- **Document auto-fill on save** (`src/lib/services/numbers.ts`): every save of a document — form (`DynamicForm.saveToDb`/`loadForm`, copies in form/list) or programmatic (`saveRecordWithLines` from runCode `save()` and flow `create`) — fills an empty `date` with today and an empty `number` with the next value: scoped to the record's year («нумерация в пределах года»), counted by the last-greatest number stripping all non-digit characters (`СП-0003` → `3`), prefix reused from the record with the max number. Applied only to tables that have `date`/`number` columns; constants and system tables are skipped, non-documents number globally (no year scope).
- **Universal field type** (`universal`, `src/lib/fields/universal.ts` + `UniversalField.svelte`, Postgres enum `column_type` extended by `supabase/migrations/0004_add_universal_column_type.sql`): a column whose per-record value is `{ t: type, v: value }` — each record in the table can hold its own type (string/datetime/number/link/etc.). Editor shows a type `<select>` + the chosen type's `FormField` (`bind:value={value.v}`). `formatFieldValue` formats by `t`; `DynamicList` resolves `t==='link'` names via the existing `linkDisplay` map; `LookupInput` with empty `targetTableId` searches **all top-level tables** (showing the table title) so links work without column config. Registered in `fieldRegistry` (auto-appears in the constructor's type list); migration 0004 adds the enum value. For constant tables: `config.manyRecords` (constructor checkbox «🗂 Несколько констант в одной таблице») turns a `constant` table into a normal list (skips the single-record auto-create/auto-open in `DynamicList.svelte`, auto-enables `create`); a periodic constant's header value is disabled **only while the record has period lines** (`hasPeriodLines`, so plain and periodic constants can share one table); `mainColName`/`mainColType` now pick the universal/`value` column (not `columns[0]`), and `PeriodsTable` renders `UniversalField` when `valueType==='universal'`.
- **Params-list field type** (`paramslist`, `src/lib/fields/paramslist.ts` + `ParamsListField.svelte`, Postgres enum `column_type` extended by `supabase/migrations/0008_add_paramslist_column_type.sql`): a visual editor for jsonb objects shaped as `{ ключ: значение }` — e.g. scenario «Параметры» (`flow_scenarios.params`, stored value stays a plain JSON object, compatible with `mergeParams`/engine). Constructor-like: each param row has a **type** selector (string/number/boolean/date/datetime/link); for `link` you then pick a target table (top-level) and get a list of `LookupInput` fields (add/remove) filtered to that table, otherwise a single value input. Per-key type/table metadata is stored inside the object under a reserved `__meta` key (`{ ключ: { type, table } }`) — the engine ignores it, existing plain params are inferred (array → link). `upgradeScenarioParamsColumn` (in `flows.ts`, called from `ensureFlowTables`) idempotently migrates existing installs: column `jsonb` → `paramslist` on server and locally. Registered in `fieldRegistry`; `formatFieldValue` renders it as `key: N` summary in lists (skipping `__meta`); `FlowRefsPanel` also skips `__meta`.
- **Constants seed** (`src/lib/state/constants.ts`): idempotent creation of «Константы» (`constants`, type `constant`) — one table for all constants — with `config.manyRecords=true`, `features.create=true`, `periodic=true` and a child tabular «Периоды» (`constants_periods`) with `period` + universal `value` columns. Value column is `universal` (per-constant type). Wired into `metadata.ensureSystemTables()` after `ensureApiQueryTables()`. It's a real synced table, not virtual; the seed only ensures existence and missing columns (never overrides user edits on the server).
- **Table types management** (`src/lib/components/dynamic/TypeConfiguratorForm.svelte` + constructor sidebar): custom types are created/deleted in the constructor («🗂 Типы таблиц»); creation copies a base type (`createTableTypeFromBase`), deletion (`Sidebar.handleDeleteType`) is blocked **only while the type has tables with records** — empty tables are deleted cascade together with the type. The **type presets editor** is a shared tab `form_SYSTEM_TYPE_CONFIGURATOR_ID` (opened via `workspace.openTypeConfigurator` — ✎ on a type row, or «🗂 Предустановки типа» in the table configurator; rendered by `Workspace.svelte`, excluded from hash sync; `recordId` = type name, switch via the header `<select>`, confirm if dirty). It edits a type's **presets**: statuses (value/label/icon/badgeClass/isReadOnly/role `posted|deleted`), features (10 toggles), fields template (auto-created columns), custom actions (read-only). Save → `saveTableTypeDefinitionDB(name, label, definition)` writes the **raw** definition (actions as-is — `showWhen`/`showWhenNot`/`disabledWhen` survive, unlike `saveTableTypeToDB`); editing a **built-in** type creates/updates an override row in `meta_table_types` (deleting that row reverts to the built-in preset). **Changing a table's type**: ConfiguratorForm «Тип таблицы» select (top-level only, transitions to/from `constant`/`system`/`tabular` forbidden) → on save `metadata.updateTableType` (server + local) + `metadata.normalizeRecordStatuses`: the table's `features`/`statusReadOnly` overrides reset to the new type's, and records whose status the new type lacks move to its first status (safe fallback = Postgres `record_status` enum values only).
- **Sync loop**: `src/lib/services/sync.ts` pulls/pushes metadata + data between Supabase and Dexie every 60s and on app start.
- **Offline DB** (`ErpOfflineCache`): 4 Dexie tables — `meta_tables`, `meta_columns`, `data_records`, `data_lines`.
- **Hierarchy (groups/folders)**: driven by the `hierarchy` feature of the table type (`directory` = on). Single source of truth is the **top-level `parent_id`** field of `data_records`; the old self-referencing link column `parent_id` («Родитель») is no longer used and is removed from `meta_columns`. `DynamicForm` auto-renders a virtual field «Группа» (`GroupField`, `src/lib/fields/GroupField.svelte`) in the form header bound to top-level `parent_id` when hierarchy is on. `GroupField` (via `LookupInput` `filter` prop) shows **only folders** (`is_folder`) and excludes the record itself, its current group and all descendants (`computeForbiddenGroups`, BFS over `parent_id`) — full cycle protection. `DynamicList` filters the tree by `r.parent_id` only; «Создать»/copy/folder-creation pass `currentFolderId` as top-level `parent_id`; `workspace.openForm(..., initialParentId)` pre-fills the «Группа» of a new record.

## Code conventions

- **Svelte 5 runes enforced** (`vite.config.ts`: `compilerOptions.runes: true`). Old Svelte syntax (`export let`, `on:click`) is blocked outside `node_modules`.
- **Prettier only**: tabs, single quotes, no trailing commas, printWidth 100, `prettier-plugin-svelte`. No ESLint.
- All logic in `.svelte.ts` rune files or plain `.ts` services. Components are thin.
- `$lib` alias maps to `src/lib/`.
- Supabase anon key is hardcoded in `src/lib/db/supabase.ts`.

## Generated files

- `.svelte-kit/` — auto-generated by `svelte-kit sync` (run via `prepare` script). Do not edit.
- Type-check requires `svelte-kit sync` to have run first (included automatically in `check` script).

## Quirks

- `engine-strict=true` in `.npmrc` enforces exact Node.js version from lockfile.
- Dev server binds to static LAN IP `10.66.66.9` — won't work on `localhost` without changing `vite.config.ts`. `https://svelte.astro3d.ru/` and `http://10.66.66.9:5173` are the same dev server (`server.host: '10.66.66.9'`, `server.port: 5173`, `server.allowedHosts: ['svelte.astro3d.ru']` in `vite.config.ts`) — development/debugging happens there.
- Supabase instance at `https://supabase.astro3d.ru` (external, not local).
- `.prettierignore` excludes `package-lock.json`, other lockfiles, and `/static/`.
