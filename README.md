# Low-Code ERP Constructor

Конструктор учётных систем в стиле 1С:Предприятие. Метаданные и данные хранятся локально в IndexedDB и синхронизируются с Supabase.

---

## Quick Start

```bash
npm install
npm run dev
```

Dev server: `http://10.66.66.9:5173`

```bash
npm run build    # production build
npm run check    # type-check
npm run format   # auto-format (Prettier)
```

## Как это работает

### Боковая панель (слева)

- Все созданные таблицы сгруппированы по типам: **Справочники**, **Документы**, **Константы**, **Сценарии**, **Системные**
- Клик по таблице открывает её список (или форму, если запись уже выбрана)
- Кнопки **Основной режим / Конструктор** переключают вид боковой панели
- В **Конструкторе** клик по таблице открывает конфигуратор метаданных
- **🔗 Открыть ссылку…** — вставить `#/t/...`, `#/r/...`, `#/l/...` (или просто id) и открыть объект
- **🕘 История** — журнал изменений: сохранения и удаления записей (см. «История изменений»)
- **🔀 Порядок меню (основной режим)** — изменить порядок групп и таблиц (в Конструкторе)

### Рабочая область

Табы: список записей + форма редактирования. Можно открыть несколько объектов одновременно.

### Конфигуратор

Две колонки:

**Левая панель**

- **➕ Новая таблица** — создать справочник или документ
- **⚙️ Типы таблиц** — управление типами. **➕** — создать новый тип на основе существующего (копирует статусы, фичи и действия). **✎** у типа открывает вкладку **«Предустановки типа»** (см. ниже). **✕** удаляет тип: если в нём остались таблицы, то удаляются только **пустые** (вместе с типом), а таблицы с данными блокируют удаление.

**Правая панель** (после выбора таблицы)

- **Реквизиты шапки** — добавлять/редактировать/удалять колонки (имя, заголовок, тип), менять порядок кнопками **▲/▼**
- **Настройки объекта** — флаги возможностей (иерархия, копирование, печать, табличные части, физическое удаление, выполнение JS-кода) + переопределение read-only по статусам
- **Табличные части** — создание подчинённых таблиц с собственными реквизитами

> Новые реквизиты по умолчанию **скрыты в списке** (видны только в форме). Чтобы показать их в списке, используйте кнопку **⚙️** в шапке списка.

### Создание таблицы

1. В Конфигураторе введите название и выберите тип (Справочник, Документ, Константа, свой тип)
2. После создания откройте таблицу в правой панели
3. Добавьте реквизиты (строки, числа, даты, булево, ссылки, JSON и др.)
4. Сохраните настройки
5. Закройте Конструктор (режим «Основной») — таблица появится в боковой панели

### Работа с записями

- **Список**: сортировка по колонкам, массовые операции (пометить на удаление, восстановить, провести). Кнопка **⚙️** включает/выключает колонки списка, кнопка **⋮** показывает меню всех действий
- **Форма**: заполнение полей, проводка/отмена, печать
- **Иерархия** (для справочников): группы/папки, двойной клик для входа в папку
- У полей-ссылок есть кнопка **✕** — очистить выбранное значение

### Уникальные ссылки (deep links)

У каждой таблицы, записи и строки табличной части есть уникальная ссылка (работает офлайн):

- `#/t/{id|имя}` — список таблицы
- `#/r/{id}` — форма записи
- `#/l/{id}` — форма записи с выделенной строкой ТЧ

Скопировать ссылку можно через меню **⋮** (строка списка), кнопку «🔗 Копировать ссылку на запись» в форме или «🔗 Копировать ссылку строки» в табличной части. Вставленная в адресную строку ссылка открывает объект; переходы по истории браузера (назад/вперёд) работают штатно. Открытия не журналируются.

### API-режим (JSON по ссылке)

Любая таблица и запись имеет «команду JSON» — данные возвращаются как JSON **без открытия формы/списка** (выполняется в браузере, офлайн):

| Ссылка                                           | Результат                                           |
| ------------------------------------------------ | --------------------------------------------------- |
| `#/t/{id}.json`                                  | Список таблицы (таблица, колонки, записи)           |
| `#/r/{id}.json`                                  | Запись (+ строки ТЧ, таблица, колонки)              |
| `#/r/{id}.execute.json`                          | Выполнить код «▶️ Выполнить» таблицы, результат     |
| `#/r/{id}.execute({city:Orenburg,lang:ru}).json` | То же, с входными параметрами (переменная `params`) |

Входные параметры пишутся JS-подобным литералом без кавычек (`{city:Orenburg}`) или строгим JSON (`{"city":"Orenburg"}`). Результат открывается в панели «API» (форматированный JSON, кнопки «Копировать URL» и «Копировать JSON»). Если у таблицы нет кода действия, но запись — **сервис** справочника «Сервисы API» (есть `base_url`), `execute` выполнит декларативный вызов `apiCall(запись, params)` и вернёт ответ сервиса — так ссылка `#/r/{сервис}.execute({...}).json` становится готовым endpoint'ом (например, погода wttr.in). Параметры также доступны в коде через `record.data` (JSON-поля самой записи).

#### Каталог «API-запросы»

Для готовых внешних запросов есть системная таблица **«API-запросы»** (в разделе меню «Интеграции»). Каждая запись — один API-вызов:

- **«Сервис»** — ссылка на запись справочника «Сервисы API» (шаблон `base_url`, метод, заголовки, прокси);
- **«Параметры (JSON)»** — значения по умолчанию (например, `{"city":"Orenburg","lang":"ru"}`);
- **«Код действия»** — опционально, если вызовами сервиса нужно управлять из кода.

Запись выполняется **декларативно** (без кода): `#/r/{запрос}.execute({...}).json` или кнопкой **▶️ Выполнить**. Параметры из ссылки/кнопки **переопределяют** дефолты записи по ключу: `{...дефолты, ...параметрыВызова}`. Пример из коробки — запрос «Погода (wttr.in)»: `#/r/{запрос}.execute({city:Moscow}).json` вернёт погоду по Москве.

### История изменений (🕘)

Сохранения и удаления записей фиксируются в системной таблице **«История»** (кнопка **🕘** в боковой панели). Каждая операция — отдельная строка: колонка **«Событие»** показывает «сохранение (статус)» или «удаление». Клик по строке «сохранение» заново открывает сохранённый объект; строки «удаление» указывают на удалённый объект. История хранит последние 50 операций и синхронизируется с сервером, как обычные данные.

### Удаление записей

Есть два способа удаления:

1. **Пометка на удаление** (как в 1С) — кнопка **❌ Пометить на удаление**. Запись остаётся на месте, но подсвечивается как удаляемая. Чтобы убрать её из базы окончательно, отметьте её и нажмите **🗑️ Удалить помеченные** (или снимите пометку кнопкой **↩️ Восстановить**).
2. **Физическое удаление** — кнопка **🗑️ Удалить** (если у типа включена возможность «Физическое удаление»). Запись удаляется сразу, без пометки.

**Внимание:** оба способа безвозвратны — запись удаляется и локально, и на сервере.

### Выполнение кода (фича «Выполнить (JS-код)»)

Если у типа таблицы включена возможность **«Выполнить (JS-код)»**, в списке и форме появляется кнопка **▶️ Выполнить**:

- В **списке** — выполняется по выбранным записям
- В **форме** — по текущей записи

Код задаётся в Конфигураторе (поле «Код действия "Выполнить"») и выполняется в браузере. Доступные переменные:

| Переменная                         | Назначение                                                       |
| ---------------------------------- | ---------------------------------------------------------------- |
| `record`                           | Текущая запись (`{ id, data, status, ... }`)                     |
| `records`                          | Выбранные записи (в форме — одна запись)                         |
| `lines`                            | Строки табличных частей текущей записи                           |
| `params`                           | Входные параметры из API-ссылки (`#/r/{id}.execute({...}).json`) |
| `db`                               | Локальная база (Dexie)                                           |
| `supabase`                         | Клиент облака (Supabase)                                         |
| `save(record, lines?)`             | Сохранить изменения записи (помечает на синхронизацию)           |
| `log(...args)`                     | Вывод в консоль браузера                                         |
| `link`                             | Уникальные ссылки (`link.get('#/r/…')`, `link.record(id)` и др.) |
| `apiCall(service, params?, body?)` | Вызов внешнего API по записи справочника «Сервисы API»           |
| `flow(recordId, params?)`          | Выполнить сценарий (тип «Сценарий») по id записи                 |

> `return` из кода показывается в панели «API»: по кнопке **▶️ Выполнить** и по API-ссылке `#/r/{id}.execute(...).json`.

Пример (HTTP-запрос и запись результата):

```js
const res = await fetch('https://wttr.in/Moscow?format=j1');
const json = await res.json();
const cur = json.current_condition[0];
record.data.temperature = cur.temp_C;
record.data.name = 'Москва: ' + cur.temp_C + '°C';
await save(record);
return json;
```

### Сервисы API и вызов внешних API

Каталог **«Сервисы API»** (справочник `api_services`) описывает внешние endpoints: `base_url` (шаблон с `${param}`), `method`, тип аутентификации (`auth_type` + `auth_param`, `api_key`), заголовки, флаг активности и описание. У сервиса может быть заполнено поле-ссылка **«Прокси»** — другой сервис-шлюз (например, `astro3d.ru/api/proxy`): тогда запрос уходит через шлюз (не нужен CORS), пустое поле — прямой `fetch` из браузера.

В коде действия сервис вызывается через `apiCall`:

```js
const natal = await apiCall(
  { ... } // запись сервиса или её id
);
```

Параметры `${param}` из `base_url` подставляются из второго аргумента (значения URL-кодируются), ответ приходит как `{ ok, status, data, raw }` (JSON с fallback на сырой текст).

Сохранённые изменения уходят на сервер автоматически при следующей синхронизации (каждые 60 секунд).

### Уведомления (Telegram / VK / E-mail)

Встроенный модуль рассылки (сид создаёт системные таблицы при старте):

- **«Сервисы API»** (`api_services`) — каталог внешних endpoints, включая сервис уведомлений `astro3d.ru/api/notify` и шлюз-прокси
- **«Каналы уведомлений»** (`notify_channels`) — код канала (`tg`, `vk`, `email`), получатель по умолчанию и поле **«Сервис уведомлений»** (какой API-сервис отправляет именно этот канал)
- **«Контакты»** (ТЧ `contragent_contacts` у контрагентов) — каналы отправки контрагента: канал + значение (Telegram chat id / VK user id / e-mail)
- **«Сообщение»** (документ `notify_messages`) — текст, вложение (файл) и табличная часть **«Получатели»**: контрагент и (необязательно) канал

Действие «▶️ Выполнить» документа «Сообщение» берёт адреса из «Контактов» контрагентов, группирует каналы по сервисам отправки и шлёт по одному запросу на каждый сервис через `apiCall`; результат записывается в реквизиты «Результат» и «Последний ответ». Ключ доступа к шлюзу задаётся один раз в поле **«Ключ доступа»** сервиса-прокси. Старый справочник «Получатели» удалён (данные перенесены в «Контакты» контрагентов).

### Сценарии (графы как в n8n)

Тип таблицы **«Сценарий»** хранит схему-граф: одна запись = один сценарий, узлы и связи — его табличные части. Собирается без единой строчки кода — всё в таблицах.

- **«Узлы»** (`flow_nodes`) — каждая строка это узел: наименование, **тип узла** (выпадающий список), ссылка на «Сервис API», параметры (JSON), необязательный код.
- **«Связи»** (`flow_links`) — рёбра графа: **Откуда / Куда** (выбор строки из «Узлы»), **роль** (`flow` — последовательная, `parallel` — параллельная ветка, `input` — дополнительный вход) и подпись.

Встроенные **типы узлов** (элементы-преобразователи):

| Тип узла   | Что делает                                                          |
| ---------- | ------------------------------------------------------------------- |
| `constant` | Читает константу по имени (`{"name":"city"}`)                       |
| `get`      | Достаёт значение из JSON по пути (`{"path":"city"}`)                |
| `api`      | Вызов внешнего API (ссылка на «Сервис API» + параметры)             |
| `template` | Формирует текст по шаблону (`${current_condition.0.temp_C}` и т.п.) |
| `find`     | Находит запись/строку ТЧ по фильтру (`{"table":"…","where":{…}}`)   |
| `create`   | Создаёт запись (+ строки ТЧ)                                        |
| `run`      | Запускает действие «▶️ Выполнить» другой таблицы                    |

Между узлами данные текут автоматически: результат любого узла доступен следующим через подстановки `${имя_узла}`, `${input}` или ключи объекта (например, `${kontragent}`). Параллельные ветки исполняются одновременно, узел ждёт все свои входы. Запуск — кнопка **▶️ Выполнить** (результат в панели «API») или API-ссылка `#/r/{сценарий}.execute({kontragent:…}).json`.

Из коробки создаётся пример **«Погода → сообщение (пример)»**: константа `city` → извлечь город → запрос погоды (wttr.in) → шаблон текста → найти канал контрагента → создать «Сообщение» → отправить.

### Синхронизация

- Автоматически каждые 60 секунд (если есть интернет)
- При запуске приложения
- После любых изменений в Конфигураторе
- Офлайн-режим: данные сохраняются локально, синхронизация отложится

Если что-то отображается неактуально (например, после обновления версии), нажмите кнопку **🔄** в правом верхнем углу — приложение выполнит полную синхронизацию, очистит локальный кэш и перезагрузит страницу.

## Типы таблиц (встроенные)

| Тип             | Описание                                         | Статусы                                 | Возможности                                               |
| --------------- | ------------------------------------------------ | --------------------------------------- | --------------------------------------------------------- |
| Справочник      | Папки/группы с иерархией                         | Записан, Помечен на удаление            | Иерархия, копирование, печать, ТЧ, пометка                |
| Документ        | Проводящиеся документы                           | Черновик, Проведен, Помечен на удаление | Проведение, копирование, печать, ТЧ, пометка              |
| Константа       | Одна запись-значение (как настройка)             | Черновик                                | Периодические значения по датам                           |
| Сценарий        | Граф-схема как в n8n: узлы и связи в ТЧ          | Черновик                                | Создание, запись, копирование, ТЧ, удаление, ▶️ Выполнить |
| Табличная часть | Подчинённая таблица для ТЧ                       | —                                       | —                                                         |
| Системная       | Внутренние таблицы (История, модуль уведомлений) | —                                       | Скрыта из списков, открывается по ссылкам                 |

Дополнительно можно создавать свои типы (например, «HTTP-запрос» для работы с внешними API) — копируются статусы, возможности и действия базового типа.

### Как добавить новый тип

В Конфигураторе → **Типы таблиц** → **Новый тип**. Укажите имя (лат.), метку и базовый тип для копирования структуры. Новый тип сразу станет доступен при создании таблиц.

### Предустановки типа и смена типа таблицы

- **Предустановки типа** (статусы записей, возможности/кнопки, шаблон полей, кастомные действия) редактируются во вкладке **«🗂 Типы таблиц» → ✎** у нужного типа, либо кнопкой **«🗂 Предустановки типа»** в конфигураторе таблицы. Вкладка общая для всех типов — тип переключается выпадающим списком в шапке. Для встроенных типов сохранение создаёт переопределение: удаление типа вернёт встроенный пресет.
- **Сменить тип таблицы** можно в конфигураторе таблицы — выпадающий список **«Тип таблицы»** (недоступен для `constant`, `system`, `tabular` и табличных частей). При сохранении фичи и переопределения таблицы сбрасываются на предустановки нового типа, а записи со статусами, которых нет в новом типе, переводятся в первый статус типа.

## Типы реквизитов

| Тип                 | Вид в форме                                                                |
| ------------------- | -------------------------------------------------------------------------- |
| Строка              | `<input type="text">`                                                      |
| Текст               | Многострочное поле                                                         |
| Число               | `<input type="number">`                                                    |
| Булево              | `<input type="checkbox">`                                                  |
| Дата                | `<input type="date">`                                                      |
| Дата и время        | Поле даты и времени                                                        |
| День рождения       | Дата + часовой пояс                                                        |
| JSON                | Текстовое поле с проверкой JSON                                            |
| Ссылка              | Поисковый автокомплит по связанному справочнику                            |
| Ссылка на строку ТЧ | Выбор строки табличной части текущей записи (для связей графа)             |
| Выбор из списка     | Выпадающий список предопределённых вариантов (например, тип узла сценария) |
| Файл                | Загрузка одного файла (до 20 МБ)                                           |
| ZIP-архив           | Несколько файлов, собираются в архив на лету                               |

### Файлы и ZIP-архивы

- **Файл** — кнопка «Выбрать файл» загружает один файл (до 20 МБ), рядом показаны имя и размер. Замену и удаление можно сделать тут же.
- **ZIP-архив** — можно добавить несколько файлов: они упаковываются в архив **прямо в браузере** и сохраняются одним значением. Кнопка «Скачать» скачивает готовый архив, отдельные файлы можно удалять из архива.
- Данные хранятся внутри записи и синхронизируются с сервером как обычный реквизит.

## Печать

Для таблицы можно создать печатную форму — HTML-шаблон с переменными `{{doc.title}}`, `{{#each lines}}...{{/each}}`.

---

## Технологии

- **Frontend**: Svelte 5 (runes), SvelteKit 2, TypeScript
- **Хранилище**: Dexie.js (IndexedDB) — офлайн, Supabase (PostgreSQL) — облако
- **Форматирование**: Prettier (табы, одинарные кавычки)
