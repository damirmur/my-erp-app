# my-erp-app

Low-code ERP system built with Svelte 5 + SvelteKit 2. Offline-first via Dexie/IndexedDB, Supabase for cloud sync.

## Commands

| Command           | Purpose                                |
| ----------------- | -------------------------------------- |
| `npm run dev`     | Dev server at `http://10.66.66.9:5173` |
| `npm run build`   | Production build                       |
| `npm run check`   | Type-check only (`svelte-check`)       |
| `npm run lint`    | Prettier format check                  |
| `npm run format`  | Prettier auto-format                   |
| `npm run prepare` | Run `svelte-kit sync` after install    |

Run `npm run check` before committing. No test suite exists.

## Architecture

- **Metadata-driven**: No hardcoded forms. Components (`DynamicForm`, `DynamicList`, `TabularSection`) render from table/column definitions fetched from IndexedDB.
- **Универсальность движка (правило «сид vs данные»)** — движок не знает ни одной предметной области (банки, погода, астрология, расписания и т.п.); всё конкретное — это **данные**, а не код. В сиды (код) включается только то, без чего движок не работает или что он читает по имени:
  - **Механизмы рантайма**: песочница (`runActionCode`, `sandbox.ts`/`sandboxPlugins.ts`), `flowRunner`/`flowElements`/`triggers`, `printer`, `sync`, `deeplink`, `numbers` (автонумерация документов), `files`, типы полей/таблиц (добавляются SQL-миграциями при развёртывании — `supabase/migrations/0002-0008`, т.е. новая БД получает их автоматически).
  - **Системные таблицы, на которые движок ссылается по имени**: `history`, `app_settings`, `print_forms` (реестр — пустой; конкретные формы это данные), `api_services` (только сервисы, реализованные на сервере и используемые движком: прокси-шлюз, уведомления, переводчик, render), `flow_scenarios`/`flow_nodes`/`flow_links`/`flow_elements` (таблицы; сами сценарии и элементы каталога — данные), `notify_channels`/`notify_messages` (+ТЧ) — таблицы; каналы, получатели и сами «Сообщения» — данные; `constants`.
  - **Универсальные примитивы песочницы** (`sandboxPlugins.ts`): `parsePdf` (PDF → текст/строки), `runCode` (исполнение кода-строки из данных в песочнице), `parseNum`/`parseAmount`/`parseDate` (`src/lib/utils/ruFormat.ts`). Примитив добавляется, только если он полезен движку в целом, а не одной предметной области.
  - Сиды **идемпотентны**: таблицы — по `name` (`ensureTable`), колонки — только недостающие (`ensureColumns`), записи — только если каталог пуст (`seedRecord` + `hasServerRows`); сид никогда не удаляет существующие записи.
- Всё остальное — **данные** (таблицы, записи, сценарии, печатные формы), доставляются в новую БД бэкапом (`exportProject`/`importProject`, вкладка «Работа с информационной базой») или создаются в конструкторе; кода-сида нет. Примеры: банковские таблицы и банки с `parser_code`, сценарий-триггер «Импорт банковской выписки», печатные формы («Сценарий», «Движение по месяцам…»), примеры сервисов/API-запросов (wttr/астро/OpenStreetMap удалены из сида; в старых установках остаются как данные до ручного удаления в конструкторе).
- **Критерий решения**: таблицу/механизм в код — только если без него движок не работает или он читает её по имени. Тестовые примеры и «демо-модули» (банк, расписания и т.п.) в код не включаются — только как данные/сценарии.
- **Single route** (`/`): Entire app is an SPA with tabbed workspace managed via `src/lib/state/workspace.svelte.ts` (Svelte 5 runes).
- **Deep links (hash)**: every table/record/ТЧ row has a unique link `#/t/{id|name}`, `#/r/{recordId}`, `#/l/{lineId}`. Parsing/building/resolution in `src/lib/services/deeplink.ts` (`parseHash`, `buildUrl`, `resolveUrl`); `resolveUrl(href)` returns `{ table, columns, record?, lines? }` — record field values live in `record.data[columnName]`. Available to `runCode` as the `link` helper. Active tab is mirrored to the hash via `replaceState` from `$app/navigation`; `hashchange` in `+page.svelte` reopens objects. **API-режим (JSON по ссылке, без открытия формы)**: `#/t/{id}.json` (список), `#/r/{id}.json` (запись+ТЧ), `#/r/{id}.execute({...}).json` (выполнить код действия таблицы по записи с параметрами) — новые kinds `listJson`/`recordJson`/`execute`, параметры разбираются `parseParamsLiteral` (JS-литерал без кавычек или JSON, безопасно, без eval); исполнение в `src/lib/services/apiCommand.ts` (`runApiCommand`) → результат в `workspace.apiResult` → панель «API» (`ApiResultModal.svelte`, рендерится в `+page.svelte`); для сценариев панель показывает пошаговые статусы узлов (`steps`: ok/error/pending, текст ошибки, время), причём панель открывается **только при ошибке** (успешный прогон не перекрывает экран), а сам прогон всегда пишется в «Историю». В `runCode` доступна переменная `params` (параметры из ссылки); `return` кодa действия показывается в панели «API» (form/list `handleRun` → `workspace.showRunResult`/`workspace.showApiResult`; `showRunResult` помечает результат сценария полем `flow` и передаёт в `showApiResult`, который для `result.flow` вызывает `recordFlowRun` — запись в историю — и открывает панель только при ошибке). Из `runCode` ссылки генерируются через `link.execute(id, params?)`/`link.recordJson(id)`/`link.listJson(id)`. Changes (saves, deletes and flow runs only — **opens are not logged**) are recorded in a real system table «История» (`meta_tables.name='history'`, `type='system'`): each operation is a separate `data_records` row via `workspace.recordHistory(tableId, title, link, 'save'|'delete'|'run', status?, extra?)` with `data = { object_title, link, opened_at, event, event_type, ...extra }`. Save events fire from `DynamicForm.saveToDb` and `saveRecordWithLines` (runCode `save()`), delete events from `physicalDeleteRecords` (titles captured from the cache before deletion), flow runs from `recordFlowRun` (extra = `{ failed, description, steps, error, result }`, event = «выполнение сценария (ошибка)»/«выполнение сценария», link ведёт на сценарий). «Событие» column shows the label; «Описание» (`description` column, ensured by `ensureHistoryColumns`) — читаемое резюме прогона (статусы шагов, ошибки, результат); rows sync like any data, capped at 50. Sidebar «🕘 История» opens it as a `DynamicList`; a row click opens the history record itself as a read-only form (`DynamicList.openRecord`, system tables open as a normal form, `DynamicForm` forces `readOnly` for `type==='system'`). Seeded idempotently by `metadata.ensureSystemTables()` (startup + start of each sync, before `pullMetadata`); `ensureHistoryColumns` adds missing columns to existing installs. See `architecture.md` → Deep Links.
- **Sidebar (main mode)** (`src/lib/components/layout/Sidebar.svelte`, liveQuery-driven): tables grouped by type, «🔗 Открыть ссылку» (paste `#/t/...`/`#/r/...`/`#/l/...` or a bare id → `workspace.openFromLink()`), «🕘 История». Group/table order is editable in Конструктор («🔀 Порядок меню») and persisted in the system table `app_settings` (`src/lib/state/settings.ts`, key `main_nav_order`, synced like data); «Сброс» restores defaults, unset → `preferredTypeOrder` + `sort_order`/`number`.
- **Notifications module** (`src/lib/state/notifications.ts`): seeded idempotently by `ensureNotificationTables()` (called from `metadata.ensureSystemTables()`). Catalog «Сервисы API» (`api_services`) with a `proxy` self-link (via proxy gateway when filled, direct fetch when empty); `notify_channels` (with `service` link → api_services); document «Сообщение» (`notify_messages`); tabular part «Контакты» of counterparties (`contragent_contacts`, parent → `counterparties`, rows: `channel` + `value`); message ТЧ «Получатели» (`notify_message_channels`, rows: `kontragent` → counterparties + optional `channel`). Legacy `notify_recipients` catalog was removed (seed no longer creates it). Seed adds only the services implemented on the server (`astro3d.ru/api`): proxy gateway «astro3d — прокси (шлюз)» (number '1'), «astro3d — уведомления» ('2'), «astro3d — переводчик» ('3'), «Renderer — HTML/SVG в PNG/PDF» ('4', `base_url` with `/api/render`); it reconciles missing default services by `name` via `serviceExists()` (idempotent re-seed for existing installs) but does NOT delete existing rows (removed example services like wttr.in/Nominatim/astro astro-services stay in old installs until manually deleted). Action code `NOTIFY_RUN_CODE` (matches server-side, updated via `RUN_CODE_LEGACY` markers) resolves recipient ids from counterparty contacts, groups by service and sends via `apiCall`. `apiCall(service, params?, body?)` (`src/lib/services/actionRunner.ts`) substitutes `${param}` (URL-encoded) in `base_url`, applies auth (`auth_type` query/header), routes through proxy (`d.proxy` link → proxy service's `base_url` + its `api_key`) with backwards compat `use_proxy === true` → `https://astro3d.ru/api/proxy`. Returns `{ ok, status, data, raw }`.
- **API-queries catalog** (`src/lib/state/apiQueries.ts`): system document «API-запросы» (`api_queries`) — each record is one external call: `service` link → api_services + `params` (jsonb defaults) + optional runCode. Seeded idempotently by `ensureApiQueryTables()` (from `metadata.ensureSystemTables()` after notifications) — table only, no example records (the «Погода (wttr.in)» seed example was removed together with its wttr service). Executed declaratively when runCode is empty: `runRecordAction` (`src/lib/services/actionRunner.ts`) merges defaults with call params via `mergeParams(record, linkParams)` = `{ ...record.data.params, ...linkParams }` (link wins by key) and calls `apiCall(service, params)`; falls back to `apiCall(record, params)` for records with own `base_url`. Form/list `handleRun` now delegate to `runRecordAction` (result → «API» panel), so ▶️ works for both coded and declarative records.
- **Bank statements** (данные + сценарий; в коде — только примитивы): таблицы `banks`/`bank_accounts`/`bank_statements`/`bank_statement_operations` и сами банки с `parser_code` — это **данные** (каталог «Банки» создаётся в конструкторе/бэкапом, кода-сида нет). Контекст кода-парсера банка (поле `parser_code`): `text`, `rows`, `helpers` (`num`/`amount`/`date`/`hint`), `record`, `params`, `db`, `supabase`, `save`, `log`, `link`, `apiCall`, `run`; возвращает `{ header, operations }`. Импорт — **сценарий-триггер «Импорт банковской выписки»** (данные, `flow_scenarios` с `trigger_table`=bank_statements, `trigger_event`=save; код-узел делает: `parsePdf(d.file)` → определить банк (поле → банк счёта → автораспознавание по `bank_hints`) → `runCode(parser_code, { text, rows, helpers, ... })` → нормализация/дедупликация (ключ `дата|время|код|сумма`) → автосоздание/привязка «Банковского счёта» → `save()` шапки+ТЧ; пустой `params.record.file` → `{ skipped: true }`, ТЧ не трогаются). «▶️ Выполнить» у выписок — ручной запуск того же сценария (runCode в конфиге таблицы). В коде программы остались только **универсальные примитивы**: `pdfText.extractPdfText` (pdf.js, ленивый import; регистрируется как `parsePdf`) + `runCode` (исполнение кода-строки из данных в песочнице) + `parseNum`/`parseAmount`/`parseDate` (`src/lib/utils/ruFormat.ts`, разбор русского формата чисел/сумм/дат) — все в `sandboxPlugins.ts`.
- **Print forms module** (`src/lib/state/printForms.ts` + `src/lib/services/printer.ts`): registry «Печатные формы» (`print_forms`, type `template` «Шаблон», `config.hiddenInMain: true` — hidden from main mode, edited in constructor) seeded idempotently by `ensurePrintFormsTable()` (from `metadata.ensureSystemTables()`; reconciles type to `template` if an earlier version created the table as `document`) + legacy migration `seedPrintFormDefaults()` in `sync.runFullSync` (copies rows from the old raw Supabase `print_forms` table — `template_html` — into `data_records`, then deletes them). Columns: `number`, `name`, `target_table` (select «Таблица» — options = all top-level tables via `flowElements.loadSelectOptions`, title shown in `DynamicList` via `tableTitleMap`), `template_html` (textarea «Шаблон HTML»), `code` (textarea «Код заполнения»), `is_default` (boolean «По умолчанию»), `delivery` (string «Способы вывода: print,screen,send,download», пусто = все), `output_format` (string html|svg — формат вывода; у формы «Сценарий» — svg), `summary` (textarea «Выжимка для сообщения», рендерится движком), `sort_order`. Кнопка «🖨️ Вывод» (`Toolbar.svelte`, liveQuery-driven) — это **меню доставки документа**: **0 форм → кнопка скрыта**, при 1 форме пункты меню — способы вывода формы, при нескольких — подменю «форма → способы» (дефолт ✓); способы определяются колонкой `delivery`. Renderer `printerService.renderRecords(tableId, recordIds, formId?)` (в `src/lib/services/printer.ts`) reads `template_html` (not `template`), возвращает `{ html, title, count, formId, format, svg?, summary }` (html — полный HTML-документ для предпросмотра/печати/скачивания; при `output_format='svg'` дополнительно извлекается `<svg>` в `svg`, `summary` — рендер колонки summary с доступом к `{{doc.*}}`/`{{sum:}}`/`{{count:}}`/`{{#each}}`, приводится к тексту через `htmlToText`) и используется всеми способами вывода: `printRecords` (окно печати, как раньше), `downloadRecords` (Blob `*.html`), «👁 На экране» — `workspace.openPrintPreview` → `PrintPreviewModal.svelte` (рендерится в `+page.svelte` рядом с `ApiResultModal`, iframe `srcdoc` + кнопка печати). Отправка «✉️ Отправить» — `src/lib/services/deliver.ts` (`deliverService.sendDocuments`): рендерит документ и создаёт **документ «Сообщение»** (`notify_messages`) с темой, **выжимкой** (`render.summary` либо авто-выжимка: таблица №, дата, контрагент, строки/сумма) и вложением-исходником — для `output_format='svg'` `<svg>` (`{title}.svg`), иначе полный HTML (`{title}.html`); **расширение файла = маркер для шлюза**. Сообщение открывается для дозаполнения получателей; если в записи есть контрагент (поле-ссылка на «Контрагенты») — предлагает (confirm) добавить его в ТЧ «Получатели» (`notify_message_channels`); при отказе/отсутствии поля получателей заполняют вручную/программно и отправляют «▶️ Выполнить» самого сообщения (НЕ отправляет сразу). Серверная сторона (`astro3d.ru`, Go): локальный сервис **renderer** (`/home/dmyr/renderer`, chromedp + chrome-headless-shell, `127.0.0.1:8099`, ключ `X-Render-Key`/query `render_key` = `RENDER_KEY`; юнит `renderer.service`, `sudoers.d/renderer` для systemctl без пароля) рендерит HTML/SVG → PNG/PDF; `astro-api` по расширению вложения: `.html` → tg/vk PNG-фото (caption=выжимка), email = `multipart/alternative` (текст+HTML-тело) + PDF-вложение; `.svg` → PNG-фото/вложение; `.png/.jpg` → фото; иначе — документом; при недоступности renderer — фолбэк документом. Каталог «Сервисы API» получает seed-сервис «Renderer — HTML/SVG в PNG/PDF» (номер '10', `base_url=https://astro3d.ru/api/render`, через прокси, `auth_param=notify_key`): из песочницы `apiCall(svc, {}, { kind: "html"|"svg", html/svg, width?, format: "png"|"pdf" })` → `{ data: base64, content_type }`. Universal mustache-like engine (`renderTemplate` in `printer.ts`): `{{field}}`/`{{doc.field}}` — any record column (formatted by type via `formatFieldValue`, link columns resolved to names), `{{doc.title}}`, `{{doc.total_amount}}` (sum of `amount` over all lines), `{{#each <ТЧ>}}…{{this.field}}…{{@index + 1}}{{/each}}` (any tabular part by name; legacy `{{#each lines}}` = first ТЧ, innermost blocks first), `{{sum:<ТЧ>:<field>}}`, `{{count:<ТЧ>}}`. **Поле `code`**: JS в песочнице `runActionCode` (контекст `record`, `records`, `lines`, `subLines` = имя ТЧ → строки, `params`, `db`, `supabase`, `save`, `log`, `link`, `apiCall`, `run`, `flowLayout`); возвращает строку HTML (используется как есть) или объект данных, который рендерится макетом через `{{form.<key>}}` / `{{#each form.<name>}}…{{this.<key>}}…{{/each}}`; ошибки кода выводятся в окне печати красным. Нет `code` → рендер макета по-старому. Банковская специфика (месячная группировка) живёт только в записи печатной формы (данные), движок её не знает. Values HTML-escaped; output opened in a print window. The old raw `print_forms` Dexie table is removed (`indexeddb.ts`, `sync.ts`, `Workspace.svelte`). Печатная форма **«Сценарий»** (для `flow_scenarios`): `code` строит SVG-схему графа через `flowLayout(subLines['flow_nodes'], subLines['flow_links'])` — волны-колонки «Шаг N», стрелки с ролями и подписями, карточки узлов с бейджами типов (📌/🪝/🌐/🖼/🔍/➕/🏃/🧩), красная рамка для узлов вне порядка + предупреждение о цикле — и возвращает `{ cards, edges, waves, cycleWarn, width, height, markerId }`, который макет рендерит в SVG через `{{#each form.cards}}`/`{{#each form.edges}}`/`{{#each form.waves}}`. Раньше схема жила в форме сценария (компоненты `FlowDiagram.svelte`/`FlowRefsPanel.svelte`) — удалены из `DynamicForm`.
- **Flow/scenario type** (`flow`, `src/lib/table-types/flow.ts` + `src/lib/state/flows.ts`): a table type «Сценарий» whose record is an n8n-like graph. Nodes and edges live in ТЧ (seed `ensureFlowTables` from `metadata.ensureSystemTables()`): «Узлы» (`flow_nodes`, rows: `name`, `element` — link → каталог `flow_elements`, `node_type` — `select` fed by `flowElements.selectOptionsFor`, `service` link → api_services, `params` jsonb — переопределения поверх элемента, `code`) and «Связи» (`flow_links`, rows: `from_node`/`to_node` — `linelink` fields, `role` flow|parallel|input, `label`). Catalog **«Элементы сценария»** (`flow_elements`, type `directory`): reusable node configs (`element_type` select, `service`, `params`, `code`, `icon` — значок типа); a node references an element and may override params/service/code — the engine merges defaults with overrides (priority: inputs > node overrides > element defaults). Записи каталога и сами сценарии создаются в конструкторе и живут только в БД — кода-сида нет (в т.ч. пример «Погода → сообщение» и его элементы: это данные, не сид). Execution engine `src/lib/services/flowRunner.ts` (`flowExecute(recordId, params)`): wave-based topological run — a node fires when all incoming edges are satisfied, ready nodes run in parallel (`Promise.all`), each node's result is added to an accumulated `context` (by node title + merged keys) so later nodes reference earlier results via `${имя_узла}`/`${input}`/`${key}` substitution; returns `{ results, last, steps }` — `steps` carries per-node status (`ok`/`error`/`pending`, error text, durationMs) shown in the «API» panel. Node types in `src/lib/services/flowElements.ts` (`runFlowElement`): `constant` (read constant by name), `get` (JSON path extract, passthrough for scalars), `api` (apiCall with `${...}` substitution), `template` (text with `${path}`), `find` (record/ТЧ-line lookup by `where`; `all: true` returns ALL matches as an array, array `where` values mean «in», `map` reshapes rows for `lines`; local IndexedDB first, then Supabase fallback — always attempted (no `navigator.onLine` gate) querying both local and server table ids, found lines cached), `create` (record + ТЧ lines via `saveRecordWithLines`; `lines` accepts an array from context), `run` (runAnotherTable). `substitute` preserves the type of an exact `${path}` value (arrays/objects), so a whole `lines` spec or a `where` list can come from context. Dispatch in `flowRunner.executeNode`: element types → `runFlowElement`, else service → apiCall, else `code` → runActionCode (context gains `flow`, `input`, `inputs` in `actionRunner.ts`; **входные параметры сценария доступны коду узла** — `params` код-узла = `{ ...scenarioParams, ...params }`). Triggered by ▶️ (runRecordAction dispatches flow type when no runCode) or default `config.runCode = return await flow(record.id, params)`. Scenario «Параметры» (jsonb) is an editable column of `flow_scenarios`; `mergeParams` merges them with link params (and parses `data.params` stored as JSON string). Field types added for this: `linelink` («Ссылка на строку ТЧ», `LineLinkField.svelte` — dropdown of a sub-table's rows for the current record, candidates passed from form memory before save) and `select` («Выбор из списка», `SelectField.svelte` — options passed per column via `selectOptionsFor`). Postgres enum values added by migrations `0006_add_linelink_column_type.sql` and `0007_add_select_column_type.sql`.
- **Scenario triggers (по-событию)** (`src/lib/services/triggers.ts`): a scenario (flow_scenarios record) can subscribe to an event of any table — columns `trigger_table` (link, все таблицы верхнего уровня, «Срабатывает для таблицы») and `trigger_event` (select «Событие»: save/post/unpost/delete; options in `flowElements.selectOptionsFor`, added idempotently to existing installs by `ensureColumns` in `ensureFlowTables`). Fired synchronously AFTER the save commits (save itself is independent — a trigger failure never rolls back the record): `fireTriggers(tableId, recordId, prevStatus, nextStatus, extra)` maps the status transition (`posted`(new)→post, `posted→draft`→unpost, `marked_for_deletion`(new)→delete, else save) → finds matching scenarios by (trigger_table, trigger_event) → runs each sequentially via `flowExecute(scenarioId, { recordId, record, event, prevStatus, nextStatus, ...extra })`. Every run is written to history via `workspace.recordFlowRun` (ok and error alike); an error is returned to the caller, which shows a popup (`DynamicForm.saveToDb`, `DynamicList` single/mass ops). Hook points: `DynamicForm.saveToDb` (prev status read from Dexie before the transaction — `recordStatus` is already the target for post/unpost; after a successful run the form is reloaded so ТЧ changes appear), `actionRunner.saveRecordWithLines` (programmatic/flow-create saves), `DynamicList` post/unpost/restore/mass ops, `records.physicalDeleteRecords` (delete event with `recordSnapshot` since the record is already gone). Recursion guard `triggerDepth` (`isTriggerActive()`): saves made INSIDE a trigger scenario do not re-fire triggers and skip their own «save» history entry. Use case: «Импорт банковской выписки» — a scenario bound to `bank_statements` on save whose code node checks `params.record.file` (empty → `return { skipped: true }`, ТЧ untouched — «удалил файл, пересохранил» keeps operations) and otherwise does the import itself on universal primitives (`parsePdf` → `runCode(parser_code)` → dedup → `save()`).
- **Document auto-fill on save** (`src/lib/services/numbers.ts`): every save of a document — form (`DynamicForm.saveToDb`/`loadForm`, copies in form/list) or programmatic (`saveRecordWithLines` from runCode `save()` and flow `create`) — fills an empty `date` with today and an empty `number` with the next value: scoped to the record's year («нумерация в пределах года»), counted by the last-greatest number stripping all non-digit characters (`СП-0003` → `3`), prefix reused from the record with the max number. Applied only to tables that have `date`/`number` columns; constants and system tables are skipped, non-documents number globally (no year scope).
- **Universal field type** (`universal`, `src/lib/fields/universal.ts` + `UniversalField.svelte`, Postgres enum `column_type` extended by `supabase/migrations/0004_add_universal_column_type.sql`): a column whose per-record value is `{ t: type, v: value }` — each record in the table can hold its own type (string/datetime/number/link/etc.). Editor shows a type `<select>` + the chosen type's `FormField` (`bind:value={value.v}`). `formatFieldValue` formats by `t`; `DynamicList` resolves `t==='link'` names via the existing `linkDisplay` map; `LookupInput` with empty `targetTableId` searches **all top-level tables** (showing the table title) so links work without column config. Registered in `fieldRegistry` (auto-appears in the constructor's type list); migration 0004 adds the enum value. For constant tables: `config.manyRecords` (constructor checkbox «🗂 Несколько констант в одной таблице») turns a `constant` table into a normal list (skips the single-record auto-create/auto-open in `DynamicList.svelte`, auto-enables `create`); a periodic constant's header value is disabled **only while the record has period lines** (`hasPeriodLines`, so plain and periodic constants can share one table); `mainColName`/`mainColType` now pick the universal/`value` column (not `columns[0]`), and `PeriodsTable` renders `UniversalField` when `valueType==='universal'`.
- **Params-list field type** (`paramslist`, `src/lib/fields/paramslist.ts` + `ParamsListField.svelte`, Postgres enum `column_type` extended by `supabase/migrations/0008_add_paramslist_column_type.sql`): a visual editor for jsonb objects shaped as `{ ключ: значение }` — e.g. scenario «Параметры» (`flow_scenarios.params`, stored value stays a plain JSON object, compatible with `mergeParams`/engine). Constructor-like: each param row has a **type** selector (string/number/boolean/date/datetime/link); for `link` you then pick a target table (top-level) and get a list of `LookupInput` fields (add/remove) filtered to that table, otherwise a single value input. Per-key type/table metadata is stored inside the object under a reserved `__meta` key (`{ ключ: { type, table } }`) — the engine ignores it, existing plain params are inferred (array → link). `upgradeScenarioParamsColumn` (in `flows.ts`, called from `ensureFlowTables`) idempotently migrates existing installs: column `jsonb` → `paramslist` on server and locally. Registered in `fieldRegistry`; `formatFieldValue` renders it as `key: N` summary in lists (skipping `__meta`); `FlowRefsPanel` also skips `__meta`.
- **Constants seed** (`src/lib/state/constants.ts`): idempotent creation of «Константы» (`constants`, type `constant`) — one table for all constants — with `config.manyRecords=true`, `features.create=true`, `periodic=true` and a child tabular «Периоды» (`constants_periods`) with `period` + universal `value` columns. Value column is `universal` (per-constant type). Wired into `metadata.ensureSystemTables()` after `ensureApiQueryTables()`. It's a real synced table, not virtual; the seed only ensures existence and missing columns (never overrides user edits on the server).
- **Table types management** (`src/lib/components/dynamic/TypeConfiguratorForm.svelte` + constructor sidebar): custom types are created/deleted in the constructor («🗂 Типы таблиц»); creation copies a base type (`createTableTypeFromBase`), deletion (`Sidebar.handleDeleteType`) is blocked **only while the type has tables with records** — empty tables are deleted cascade together with the type. The **type presets editor** is a shared tab `form_SYSTEM_TYPE_CONFIGURATOR_ID` (opened via `workspace.openTypeConfigurator` — ✎ on a type row, or «🗂 Предустановки типа» in the table configurator; rendered by `Workspace.svelte`, excluded from hash sync; `recordId` = type name, switch via the header `<select>`, confirm if dirty). It edits a type's **presets**: statuses (value/label/icon/badgeClass/isReadOnly/role `posted|deleted`), features (10 toggles), fields template (auto-created columns), custom actions (read-only). Save → `saveTableTypeDefinitionDB(name, label, definition)` writes the **raw** definition (actions as-is — `showWhen`/`showWhenNot`/`disabledWhen` survive, unlike `saveTableTypeToDB`); editing a **built-in** type creates/updates an override row in `meta_table_types` (deleting that row reverts to the built-in preset). **Changing a table's type**: ConfiguratorForm «Тип таблицы» select (top-level only, transitions to/from `constant`/`system`/`tabular` forbidden) → on save `metadata.updateTableType` (server + local) + `metadata.normalizeRecordStatuses`: the table's `features`/`statusReadOnly` overrides reset to the new type's, and records whose status the new type lacks move to its first status (safe fallback = Postgres `record_status` enum values only).
- **Solution packs** (`src/lib/services/solutionPacks.ts` + `src/lib/state/solutions.ts`): универсальный механизм переноса целого модуля между базами **целиком в данных** (движок не знает ни одной предметной области). Системная таблица `solution_packs` (модуль 'solutions', группа `core`, type `template`, `hiddenInMain: true`, колонки: `name`, `description`, `definition` (jsonb «Определение»), `applied_at`); действие «▶️ Выполнить» = `config.runCode` `APPLY_SOLUTION_RUN_CODE` → примитив песочницы `applySolution(record.data.definition, { dryRun })` (зарегистрирован в `sandboxPlugins.ts`, рядом `validateSolution`). **Формат пакета** (`SolutionPack`, `my-erp-solution`/v1): `id`/`title`/`requires` (`engine` — версия движка `ENGINE_VERSION`, `packages` — по записям `solution_packs`), `tableTypes` (raw definition предустановок типов), `tables` (таблицы+колонки+ТЧ: `parent` — имя родителя, `relatedTable` — имя таблицы для link/linelink), `seedRecords` (записи каталогов по имени таблицы, `key` + `match`-поля), `scenarios` (граф: `nodes`/`links` с ключами узлов, `triggerTable`/`triggerEvent`/`params`), `printForms`. **Ссылки**: `@key` (запись-сид), `@sys:table/имя` (существующая запись базы), `@table:имя` (id таблицы — для `trigger_table`/`target_table` и колонок-схем), `@ln:ключ` (строка ТЧ текущей записи, ключ = `__id` строки). Применение (`applySolution`) — на идемпотентных `ensureTable`/`ensureColumns`/`seedRecord` + собственный `seedLines` (двухфазно: сначала всем строкам выделяются id — поэтому `@ln:` может указывать вперёд): таблицы по `name`, колонки — только недостающие, типы — если нет строки в `meta_table_types`, записи — если нет совпадения по `match` (по умолчанию `name`; пропущенные всё равно регистрируются в `recordKeys` → `@key` ссылки разрешаются к существующим id). `scenarios`/`printForms` превращаются в `RecordSeed` (kind `scenario`/`printForm`) и идут тем же конвейером. Отчёт (`ApplyReport`) показывается в панели «API» (ошибки/предупреждения/созданное); после изменения схемы вызывается `bumpMetaVersion()`. Обратная операция `exportSolution({ tableNames, id, title, includeRecords })`: читает с сервера выбранные таблицы (+ТЧ автоматически) и превращает в пакет — ссылки link/linelink/jsonb на записи области → `@key`/`@ln:`, на таблицы → `@table:`; `includeRecords:false` — только схема без записей. UI в «Работе с информационной базой» (`InfoBaseConfigurator.svelte`): «📦 Экспорт пакета» (чекбоксы таблиц верхнего уровня → `downloadSolution`) и «📦 Импорт пакета» (`parseSolutionFile` → `validatePack` → создаёт запись в реестре через `seedRecord` → опционально `applySolution`). `SYSTEM_SEED_VERSION` поднят до 2 (добавление модуля в core).
- **Sync loop**: `src/lib/services/sync.ts` pulls/pushes metadata + data between Supabase and Dexie every 60s and on app start.
- **Offline DB** (`ErpOfflineCache`, Dexie version 5): 5 tables — `meta_tables`, `meta_columns`, `data_records`, `data_lines`, `data_files` (attachments).
- **Hierarchy (groups/folders)**: driven by the `hierarchy` feature of the table type (`directory` = on). Single source of truth is the **top-level `parent_id`** field of `data_records`; the old self-referencing link column `parent_id` («Родитель») is no longer used and is removed from `meta_columns`. `DynamicForm` auto-renders a virtual field «Группа» (`GroupField`, `src/lib/fields/GroupField.svelte`) in the form header bound to top-level `parent_id` when hierarchy is on. `GroupField` (via `LookupInput` `filter` prop) shows **only folders** (`is_folder`) and excludes the record itself, its current group and all descendants (`computeForbiddenGroups`, BFS over `parent_id`) — full cycle protection. `DynamicList` filters the tree by `r.parent_id` only; «Создать»/copy/folder-creation pass `currentFolderId` as top-level `parent_id`; `workspace.openForm(..., initialParentId)` pre-fills the «Группа» of a new record.

## Code conventions

- **Svelte 5 runes enforced** (`vite.config.ts`: `compilerOptions.runes: true`). Old Svelte syntax (`export let`, `on:click`) is blocked outside `node_modules`.
- **Prettier only**: tabs, single quotes, no trailing commas, printWidth 100, `prettier-plugin-svelte`. No ESLint.
- All logic in `.svelte.ts` rune files or plain `.ts` services. Components are thin.
- `$lib` alias maps to `src/lib/`.
- Supabase anon key is hardcoded in `src/lib/db/supabase.ts`.

## Generated files

- `.svelte-kit/` — auto-generated by `svelte-kit sync` (run via `prepare` script). Do not edit.
- Type-check requires `svelte-kit sync` to have run first (included automatically in `check` script).
